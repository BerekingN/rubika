# ربات مدیریتی + سلف روبیکا (نسخه‌ی Railway)

این پروژه با کتابخانه‌ی **[rubpy](https://github.com/shayanheidari01/rubika)**
نوشته شده و برای اجرا روی **Railway** آماده است.

## ⚠️ نکته‌ی مهم درباره‌ی این نسخه — لطفاً اول بخوانید

1. **بدون ارسال خودکار و تکرارشونده به گروه‌ها.** بخش «بنر» فقط با دستور
   *دستی* خودتان ارسال می‌شود، یا حداکثر یک *یادآوری* به خودتان می‌فرستد که
   وقت ارسال بنر رسیده — نه بیشتر. ارسال خودکار و مکرر پیام یکسان به چند
   گروه در هر پیام‌رسانی (روبیکا هم همینطور) به‌عنوان اسپم شناسایی می‌شود و
   می‌تواند اکانت شخصی شما را محدود یا بن کند. این تصمیم عمدی است و برای
   حفاظت از اکانت شماست.

2. **کتابخانه‌ی rubpy غیررسمی و به‌سرعت در حال تغییر است.** بین نسخه‌های
   مختلف آن (v5 تا v7) نام کلاس‌ها و متدها عوض شده. این کد بر اساس آخرین
   مستندات عمومی نوشته شده، اما **قبل از دیپلوی روی Railway حتماً یک‌بار
   `main.py` را لوکال تست کنید**. اگر با خطای `AttributeError` یا شبیه آن
   مواجه شدید (مثلاً نام متدی مثل `send_message` یا فیلد `object_guid` در
   نسخه‌ی نصب‌شده‌ی شما فرق دارد)، مستندات فعلی را اینجا ببینید:
   https://docs.rubpy.site/ و اسم متد/فیلد را در `main.py` جایگزین کنید.
   من نمی‌توانم صحت ۱۰۰٪ این نام‌ها را برای نسخه‌ای که شما نصب می‌کنید
   تضمین کنم، چون کتابخانه مدام آپدیت می‌شود.

## این نسخه شامل چه چیزی است؟

- مدیریت گروه‌ها و ادمین‌ها
- بنر تبلیغاتی **دستی**: ثبت با ریپلای، پیش‌نمایش، ارسال با یک دستور
- یادآوری بنر (فقط یادآوری، نه ارسال خودکار)
- منشی خودکار در پیوی + پرسش و پاسخ
- سکوت (خاموش‌کردن کامل پاسخ‌های خودکار)
- بازی و سرگرمی: تاس، سکه، سنگ‌کاغذقیچی، حدس عدد، چالش، جوک، فال
- ساعت و تاریخ (شمسی)
- ماشین‌حساب امن
- یادداشت، یادآوری زمان‌دار، ذخیره‌ی سریع پیام با برچسب («سیو»)

## پیش‌نیازها

- پایتون ۳.۱۰ یا بالاتر روی سیستم شخصی خودتان (برای مرحله‌ی ورود)
- یک اکانت Railway برای دیپلوی نهایی

## مرحله‌ی ۱: ورود به اکانت روبیکا (فقط یک‌بار، روی سیستم خودتان)

این مرحله را حتماً روی کامپیوتر یا موبایل خودتان انجام دهید، **نه روی
Railway** — سرورهای دیتاسنتر گاهی هنگام درخواست کد ورود مسدود می‌شوند.

```bash
pip install -U rubpy
python login_local.py
```

شماره تلفن، کد پیامکی (و در صورت فعال بودن، رمز دومرحله‌ای) از شما پرسیده
می‌شود. بعد از موفقیت، فایلی به اسم `rubika_session.session` همان‌جا ساخته
می‌شود — این فایل معادل رمز کامل اکانت شماست، جایی به اشتراک نگذارید.

## مرحله‌ی ۲: تبدیل سشن به یک متغیر قابل‌انتقال

```bash
python session_to_env.py
```

این دستور یک رشته‌ی طولانی (base64) چاپ می‌کند. آن را کپی کنید.

## مرحله‌ی ۳: دیپلوی روی Railway

1. یک پروژه‌ی جدید در Railway بسازید و همین فایل‌ها (`main.py`, `Procfile`,
   `requirements.txt`) را دیپلوی کنید. (فایل‌های `login_local.py` و
   `session_to_env.py` فقط برای اجرای لوکال هستند؛ نیازی نیست روی Railway
   باشند، ولی وجودشان هم مشکلی ایجاد نمی‌کند.)
2. در بخش **Variables** پروژه، این متغیرها را اضافه کنید:

   | نام متغیر | مقدار |
   |---|---|
   | `SESSION_B64` | همان رشته‌ای که مرحله‌ی ۲ چاپ کرد |
   | `OWNER_GUID` | گویدِ اکانت خودتان (اختیاری ولی توصیه‌شده — پایین‌تر توضیح داده شده) |

3. Deploy را بزنید. در لاگ باید پیام «کلاینت سلف روبیکا متصل شد» را ببینید.

### گرفتن OWNER_GUID

بعد از اولین اتصال موفق، در لاگ Railway یا با فرستادن دستور `آیدی` به
خودتان (در Saved Messages / چت با 'me') گویدتان نمایش داده می‌شود. آن را
در Variables به‌عنوان `OWNER_GUID` قرار دهید و دوباره Deploy کنید، تا فقط
خودتان بتوانید دستورات مدیریتی بدهید.

## لیست دستورات

اکثر دستورات را در چت با خودتان (`me` / Saved Messages) بفرستید. دستور
«ثبت بنر» را می‌توانید مستقیم داخل خود گروه هم (با ریپلای) بفرستید.

### عمومی
- `راهنما`
- `پینگ`
- `آیدی`

### گروه‌ها
- `افزودن گروه <guid>` — گوید گروه را از تنظیمات یا لینک گروه پیدا کنید
- `لیست گروه‌ها`
- `حذف گروه <شماره>`

### بنر (دستی)
- `ثبت بنر` — با ریپلای روی پیام بنر
- `بنر` — پیش‌نمایش بنر ذخیره‌شده
- `ارسال بنر <شماره یا all>` — ارسال فوری و یک‌باره، با فاصله‌ی ۲ ثانیه بین گروه‌ها
- `یادآوری بنر روشن <دقیقه>` — مثلاً هر ۳۰ دقیقه یک پیام یادآوری به خودتان
- `یادآوری بنر خاموش`
- `یادآوری بنر وضعیت`
- `تایید ارسال` — بعد از دیدن یادآوری، همان لحظه بنر را به همه‌ی گروه‌ها می‌فرستد

### منشی
- `منشی روشن` / `منشی خاموش` / `منشی متن <پیام>`
- `پرسش پاسخ افزودن <سوال> | <جواب>` / `پرسش پاسخ حذف <سوال>` / `لیست پرسش پاسخ`

### امنیت
- `سکوت روشن` / `سکوت خاموش`
- `افزودن ادمین <guid>` / `حذف ادمین <guid>` / `لیست ادمین‌ها`

### بازی و سرگرمی
- `تاس` / `سکه` / `سنگ کاغذ قیچی <سنگ|کاغذ|قیچی>`
- `حدس عدد` — بعد فقط عدد بفرستید
- `چالش` — سؤال چهارگزینه‌ای
- `جوک` / `فال`

### ساعت، تاریخ و ابزار
- `ساعت` / `تاریخ`
- `حساب <عبارت>` — مثال: `حساب (12+3)*2`

### یادداشت و یادآوری
- `یادداشت افزودن <متن>` / `لیست یادداشت‌ها` / `حذف یادداشت <شماره>`
- `یادآوری <دقیقه> <متن>` — مثال: `یادآوری 10 زنگ بزن به علی`
- `سیو <برچسب>` (با ریپلای) / `لیست سیو` / `نمایش سیو <برچسب>`

## نکات مهم

- **پایداری داده‌ها روی Railway**: فایل `bot_data.json` (تنظیمات، بنر،
  یادداشت‌ها و...) روی دیسک محلی سرویس ذخیره می‌شود و ممکن است با هر
  Redeploy از صفر شروع شود، مگر یک **Volume** به سرویس متصل کنید.
- **یادآوری‌های در حال انتظار فقط در حافظه (RAM) نگه‌داری می‌شوند** و با
  ری‌استارت سرویس از بین می‌روند.
- **`SESSION_B64` را در اختیار کسی قرار ندهید** — معادل رمز کامل اکانت شماست.
- فاصله‌ی «ارسال بنر» بین گروه‌ها عمداً ۲ ثانیه است تا شبیه رفتار انسانی
  بماند؛ حتی برای ارسال دستی، تعداد گروه‌های هدف را معقول نگه دارید.

## عیب‌یابی سریع

| مشکل | راه‌حل |
|---|---|
| خطای `AttributeError` روی متدها/فیلدهای rubpy | مستندات فعلی https://docs.rubpy.site/ را ببینید؛ نسخه‌ی نصب‌شده ممکن است API متفاوتی داشته باشد |
| بعد از هر دیپلوی دوباره باید لاگین کنم | `SESSION_B64` را درست در Variables ذخیره نکرده‌اید، یا Volume برای `bot_data.json` وصل نیست |
| دستورات جواب نمی‌دهند | لاگ Railway را چک کنید؛ ممکن است `OWNER_GUID` اشتباه ست شده و پیام‌ها فیلتر می‌شوند |
| ورود روی Railway با خطا مواجه می‌شود | این پیش‌بینی‌شده است — ورود را طبق «مرحله‌ی ۱» فقط لوکال انجام دهید |
